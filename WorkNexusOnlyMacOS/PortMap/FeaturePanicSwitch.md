# FeaturePanicSwitch (lib/features/panic_switch → Sources/FeaturePanicSwitch)

"Thầy vô" (boss alert): two triggers side by side. **Official**: the pet's gesture sends the "Thầy vô" sticker to the team group; every WorkNexus (Flutter or native) in the group that receives it — and the sender's own, first — opens the chosen apps (the first on top) and hides every other running app, WorkNexus included. **Demo** (demo mode only): "Demo" in the pet's right-click menu sends the demo sticker to a chat of your own; only computers in demo mode on that chat switch. Offered only to users signed in to `https://zentao.oasoft.xyz:4433/zentao`; the team group is found by name ("VN Mobile Tester", letters and digits only). Ported up to upstream `c4667502` (5321fc67, cbf7d165, 522afe59, 5a9867c8, 0252dd52, 27f8880a, c4667502, b550fdeb, fae9aaf9) plus the Thầy vô page of 4211313d.

Public entry: `PanicSwitchFeature.makeModel(settingsFile:sticker:chats:accounts:)` → `PanicSwitchModel` (`start()`, `stop()`, `edit(_:)`, `petArmed`, `petGesture`, `demoAvailable`, `petTriggered(_:)`, `watchChats(selfTitle:)`, `loadMembers()`, `loadApps()`), `PanicSwitchSettingsCard(model:initiallyExpanded:)`. Chat is reached only through the module's own `PanicChatGateway` (features never import each other): `App/Sources/PanicSwitchWiring.swift` (`ChatPanicGateway`) adapts `FeatureChat.ChatRepository` to it, and `CompositionRoot` starts the model with the app (not in demo mode). The card has its own page in the Settings sidebar (`panicSwitch`, after Translation), listed only while the oasoft ZenTao account is there (`ShellHost.settingsSectionVisible`), shown open and without its header (`appExpandableCardFlat()`, the `AppExpandableCardScope` / `AppFlatCard` of 4211313d); it is no longer on Settings › General.

**Trigger: the pet, not a floating button (native decision).** `HostWiring` fills `ShellHost.petTripleTap` (the gesture: press and hold for `petHoldSeconds` 1–30 s, default 3; double-click; triple-click — `PetAlertGesture`, counted by `CoreUI.PetTapCounter`) → `model.petTriggered(.release)`, and `ShellHost.petDemo` (non-nil while `demoAvailable`) → "Demo" heading the pet's right-click menu, in the window (`PetLayer` `.contextMenu`, only over the pet) and floating (`FloatingPetContent`) → `model.petTriggered(.demo)`. SharedKit never imports the feature. The pet must be shown (Settings › Pet). Both triggers need `enabled` and `overlayVisible` (the "Alert from the pet" switch of the Pet tab, upstream's "Show the floating button"); like upstream's button they switch here first, then send, so they work with the chat server down.

**Interop with the Flutter app.** Both send a sticker the same way: `sendFile(name: <reserved name>, bytes: thay_vo.png, mimeType: "image/png")` → the chat server stores the upload and the message goes out as content type `image` with content `{"name":<reserved name>,"size":…,"send":true,"type":"image/png","id":…,"time":…,"width":…,"height":…}` (`ChatAttachmentLoader.upload`, same as chat_attachment_loader.dart). Reserved names (`PanicTrigger.stickerFileName`): official `worknexus-thayvo-v1.png`, demo `worknexus-thayvo-demo-v1.png`. The bytes are `App/Resources/Stickers/WorkNexus/thay_vo.png`, the very file of the Flutter `assets/stickers/WorkNexus/thay_vo.png` (`Scripts/sync-assets.sh`). Both recognise them the same way: an image message whose file name, lowercased, is one of the reserved names (the server gives each upload a new id, so the name is the identity), sent no more than 30 s before or after now, in that trigger's chat (official: `chatGid`; demo: `demoChatGid` while `demoMode`), not by you; the sender allowlist applies to the team group only; each trigger has its own debounce. Settings are the same JSON object as the Flutter app's `panic_switch.config` value — `enabled`, `overlayVisible`, `chatGid`, `demoMode`, `demoChatGid`, `anySender`, `allowedSenderIds`, `appsToOpen` (`[{id,name}]`), `debounceSeconds` — plus the native `petGesture` (`hold` / `doubleClick` / `tripleClick`) and `petHoldSeconds`, kept in `<Application Support>/panic_switch.json`. Read with upstream's migrations: `chatIsSelf` and the `test…` keys (`testMode`, `testChatGid`, `testReceiveChatGid`, `testSendChatGid`) become demo mode, `targetApp` becomes `appsToOpen`; `appsToHide`, `hideSelf`, `testChatIsSelf` are dropped.

macOS only: the Windows layered window / foreground workaround, the Linux GTK window, wmctrl/xdotool/gtk-launch switcher and the Wayland note are not ported (`AppSwitcher.canRaiseApps` dropped). Left out: the floating button tab's size and fade (`overlaySize`, `overlayOpacity`, `PanicButtonLook`) and `overlayGesture` (the pet has `petGesture`); `appIcon` on `AppSwitcher` (icons come from `PanicAppIcons` through LaunchServices). Adapted: "Hide every other app" is `NSWorkspace.runningApplications` with the regular activation policy (Dock icon) but WorkNexus and the apps to open, as macos/Runner/PanicSwitchChannel.swift; the app checklist and allowlist rows use `CoreUI.AppCheckMark` (lib/core/widgets/app_check_mark.dart) and `UserAvatar`; the incoming listener checks the reserved file names off the main thread before anything else; the chats are watched only while the settings card is on screen, or until the team group is found. Still in the module from the earlier port, unused by the pet trigger: `PanicOverlay` / `PanelPanicOverlay` / `TripleClickCounter`.
